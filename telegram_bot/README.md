# ربات تلگرام Personal Hub

بازطراحی کامل با **aiogram 3.x**، تجربه کاربری کامل با دکمه‌های منویی (Reply Keyboard) و شیشه‌ای (Inline Keyboard) با **رنگ واقعی** (سبز/قرمز/آبی)، فرم‌های چند مرحله‌ای (FSM)، اتصال حساب با کد یکبار مصرف، و یادآورهایی که واقعاً سر وقت ارسال می‌شوند.

> **درباره رنگ دکمه‌ها:** برخلاف چیزی که قبلاً اینجا گفته بودم، تلگرام واقعاً یک فیلد `style` رسمی به دکمه‌ها اضافه کرده (Bot API 9.4، فوریه ۲۰۲۶): `'success'` سبز، `'danger'` قرمز، `'primary'` آبی. در aiogram از نسخه ۳.۲۶ به بعد با `style="success"` روی هر دکمه قابل استفاده‌ست و همینجا هم پیاده شده (فایل `keyboards/inline.py`). **نیازمند `aiogram>=3.26.0`** است -- `requirements.txt` اصلی پروژه به‌روزرسانی شد. اگر با نسخه قدیمی‌تر اجرا کنید، دکمه‌ها بدون رنگ ولی کاملاً کارکردی نمایش داده می‌شوند.

## اجرا

```bash
export TELEGRAM_BOT_TOKEN="توکن ربات شما از BotFather"
python manage.py migrate          # برای ساخت جدول TelegramLinkCode
python manage.py runbot           # اجرای ربات با polling
```

## ساختار پوشه

```
telegram_bot/
├── bot.py                  # نقطه ورود: Dispatcher، Middleware، اتصال روترها
├── models.py               # TelegramLinkCode (کد اتصال حساب)
├── states.py               # FSM StatesGroup برای فرم‌های چند مرحله‌ای
├── middlewares.py          # DjangoUserMiddleware: کاربر جنگو را برای هر پیام پیدا می‌کند
├── utils.py                # همه‌ی دسترسی‌های ORM (async) + فرمت‌دهی و پارس تاریخ/مبلغ
├── scheduler.py            # 🔔 حلقه‌ی پس‌زمینه: هر ۲۰ ثانیه یادآورهای سررسیدشده را واقعاً ارسال می‌کند
├── views.py / urls.py      # وبهوک (اختیاری) + API اتصال/قطع اتصال حساب برای سایت/اپ
├── admin.py, migrations/   # مدیریت TelegramLinkCode در پنل ادمین
├── keyboards/
│   ├── menus.py            # منوی پایین صفحه (Reply Keyboard) - همیشه ثابت
│   └── inline.py           # همه دکمه‌های شیشه‌ای: لیست‌ها، ویزاردها، تاییدها، صفحه‌بندی
└── handlers/
    ├── __init__.py          # همه روترها اینجا جمع می‌شوند (all_routers)
    ├── _shared.py           # کمکی مشترک: require_linked()
    ├── common.py            # /start /help /menu /cancel /settings + پیام نامشخص
    ├── linking.py           # اتصال/قطع اتصال حساب با کد یکبار مصرف
    ├── habits.py            # لیست/ثبت/آمار/فعال‌سازی/حذف عادت + ویزارد افزودن
    ├── todos.py             # لیست/تکمیل/حذف کار + ویزارد افزودن (عنوان→اولویت→سررسید)
    ├── finance.py           # خلاصه مالی/تراکنش‌های اخیر/حذف + ویزارد افزودن تراکنش
    └── reminders.py          # لیست/فعال‌سازی/حذف یادآور + ویزارد افزودن
```

## دستورات ربات

| دستور | کاربرد |
|---|---|
| `/start` | شروع + وضعیت اتصال حساب |
| `/menu` | نمایش منوی اصلی (دکمه‌های پایین صفحه) |
| `/habits` | لیست و مدیریت عادت‌ها |
| `/todos` | لیست و مدیریت کارها |
| `/balance` | خلاصه مالی و ثبت تراکنش |
| `/reminders` | لیست و مدیریت یادآورها |
| `/settings` | تنظیمات و قطع اتصال حساب |
| `/link` | دریافت کد اتصال حساب |
| `/cancel` | لغو فرم چند مرحله‌ای جاری |
| `/help` | راهنما |

همه این دستورات از طریق منوی پایین صفحه (دکمه‌های 📋 ✅ 💰 🔔 ⚙️ ❓) هم در دسترس‌اند.

## اتصال حساب

حالا یک اپ کامل به اسم **`webapp/`** ساخته شده که کل این فرآیند رو برای کاربر عادی (بدون تایپ کد، بدون زدن API دستی) انجام می‌ده -- جزئیات کامل در README اصلی پروژه، بخش «مینی‌اپ تلگرام + سایت». خلاصه‌ی مسیرها:

1. **مینی‌اپ (بهترین حالت، صفر تایپ)** -- وقتی `MINI_APP_URL` ست شده باشه، دکمه‌ی «🔗 اتصال حساب» مستقیم مینی‌اپ رو باز می‌کنه. کاربر ثبت‌نام/ورود می‌کنه و هویت تلگرامش از طریق `Telegram.WebApp.initData` امضاشده (`telegram_bot/webapp_auth.py`) خودکار تایید و وصل می‌شه:
   ```
   POST /api/telegram/webhook/webapp-link/
   Authorization: Bearer <JWT>
   {"init_data": "<Telegram.WebApp.initData>"}
   ```

2. **لینک عمیق + QR (بدون مینی‌اپ، ولی هنوز بدون تایپ)** -- سایت با یک درخواست احراز‌هویت‌شده یک لینک `https://t.me/...` می‌گیره و به‌صورت QR یا دکمه نشون می‌ده؛ لمس/اسکن آن باعث می‌شه ربات خودش با دیتابیس همون چت رو وصل کنه:
   ```
   POST /api/telegram/webhook/generate-link/   -> {"deep_link": "..."}
   GET  /api/telegram/webhook/link-status/     -> {"linked": true/false}  (سایت هر ۲-۳ ثانیه پول می‌کنه)
   ```

3. **کد دستی (فقط راه جایگزین/اضطراری)** -- کاربر در ربات `/link` می‌زنه، کد ۶ رقمی می‌گیره، و در سایت وارد می‌کنه:
   ```
   POST /api/telegram/webhook/verify-link/
   Authorization: Bearer <JWT>
   {"code": "123456"}
   ```

قطع اتصال هم برای هر سه حالت یکسانه:
```
POST /api/telegram/webhook/unlink/
Authorization: Bearer <JWT>
```

> نکته مسیر: چون این‌ها داخل `telegram_bot/urls.py` تعریف شده‌اند و آن اپ در
> `personal_hub/urls.py` روی `api/telegram/webhook/` مونت شده، آدرس نهایی
> کمی طولانی می‌شود (`.../webhook/verify-link/`). برای تمیزتر شدن
> (`/api/telegram/verify-link/`)، کافیست در `personal_hub/urls.py` مقدار
> prefix همان include را به `api/telegram/` تغییر دهید.

## یادآورها الان واقعاً یادآوری می‌کنند 🔔

قبلاً یادآور فقط با زدن `/reminders` نمایش داده می‌شد. حالا همزمان با polling ربات،
یک تسک پس‌زمینه (`scheduler.py`) هر ۲۰ ثانیه دیتابیس رو چک می‌کنه:

- هر یادآور فعالی که `remind_at` آن رسیده باشه، مستقیم برای کاربر پیام می‌فرسته.
- اگر یادآور **تکراری** باشه (روزانه/هفتگی/ماهانه/سفارشی)، خودش زمان بعدی رو
  محاسبه و ذخیره می‌کنه (با احترام به `recurrence_end_date` اگر ست شده باشه).
- اگر یادآور یک‌باره باشه، بعد از ارسال غیرفعال می‌شه.
- اگر ربات یک مدت خاموش بوده، یادآورهای تکراری به‌جای ارسال انبوه پیام‌های
  قدیمی، مستقیم به نزدیک‌ترین زمان آینده منتقل می‌شن.

نیازی به سلری یا Redis نیست -- برای یک ربات شخصی همین حلقه‌ی ساده‌ی asyncio
کاملاً کافیه و همراه با `python manage.py runbot` بالا میاد.

## افزودن یک قابلیت جدید (مثلاً «یادداشت‌ها»)

1. اگر مدل جدید لازم است، در اپ جنگوی مربوطه (یا اپ جدید) بسازید.
2. توابع دسترسی به دیتابیس (async) را در `utils.py` اضافه کنید.
3. کیبوردهای لازم را در `keyboards/inline.py` اضافه کنید.
4. یک فایل `handlers/notes.py` با یک `Router` جدید بسازید (از روی `habits.py` کپی بگیرید، ساختار مشابه است).
5. روتر جدید را در `handlers/__init__.py` به `all_routers` اضافه کنید.

همین! نیازی به تغییر `bot.py` یا هیچ فایل دیگری نیست.
